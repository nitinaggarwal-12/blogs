Reference Architecture Taxonomy & 5-Hop Governance Baseline

Audience: Cloud Architects, AI Platform Engineers, CISOs & B2B SaaS Platform Leads
🟧 Google Slides ↗ 🟦 Google Doc ↗ 🐙 GitHub MD ↗

1. Executive Thesis & Core Problem Solved

Stateful multi-turn agents running on Vertex AI Agent Engine, ADK, and Gemini Enterprise introduce shared LLM context caches, dynamic MCP tool calls, multi-level memory banks, and customer-authored private agents. Blog 1 establishes that isolation is a per-tenant tier decision, not a single platform-wide compromise—decoupling an 80% reusable 5-Hop Cryptographic Context Chain from the 20% perimeter delta across Pooled (Pattern A), Sovereign Silos (Pattern B), and Dynamic Hybrid (Pattern C).

2. Core Technical Architecture & 5-Hop Isolation Mechanics

  • Hop 1 — Edge & Identity PEP (hop1_edge_identity_pep.py): Cloud Armor & IAP strip spoofed X-Tenant-Id headers, execute RFC 8693 OBO + RFC 9449 DPoP proofs (jkt), and sign immutable TenantContext digests via Cloud KMS (EC-P256).
  • Hop 2 — ARD Catalog & Callback PDP (hop2_registry_pdp_callbacks.py): Filters Discovery Engine / Agent Registry catalogs and prunes unauthorized tools via ADK before_agent_callback (blocking RetailStream from FinVault's private Agent Alpha with HTTP 403).
  • Hop 3 — Compute, 5-Level Memory & Bulkheads (hop3_compute_finops_bulkhead.py): Binds gVisor temp:tenant_id, isolates L1–L5 memory, enforces Valkey rate buckets (HTTP 429), and yields up to 90% COGS savings via ContextCacheConfig.
  • Hops 4 & 5 — Model Armor, SDP & AlloyDB RLS (hop4 • hop5): Blocks prompt injection (HTTP 400) & Semantic NLCs (HTTP 422), scrubs IBAN/SSN PII, binds SET LOCAL app.current_tenant_id on AlloyDB RLS, and streams zero-PII BigQuery OTel spans.

Pattern A: High-Density Pooled Multi-Tenant Architecture

Audience: Cloud Architects, AI Platform Engineers, FinOps Leads & CISOs at B2B SaaS Organizations
🟧 Google Slides ↗ 🟦 Google Doc ↗ 🐙 GitHub MD ↗

1. Executive Thesis & Core Problem Solved

Standard B2B SaaS tiers serving hundreds of competing organizations cannot provision dedicated GCP projects per tenant without collapsing gross margins. Pattern A (High-Density Pooled Architecture) runs competing corporate tenants inside one shared Google Cloud project (cymbal-pooled-prod) while cutting shared input-token COGS by 90% (84.7% total turn COGS reduction) and blocking 10/10 red-team cross-tenant breach simulations.

2. Core Technical Architecture & 5-Hop Isolation Mechanics

  • Shared Prefix Caching Without Bleed: Caches immutable platform prompts & tool schemas once via Vertex AI ContextCacheConfig while injecting per-tenant Firestore prompts, GCS Skills URIs, and L1–L4 memory post-cache in Hop 3.
  • Multi-IdP 3LO Federated Sandbox: Simultaneously brokers Google OIDC (Workspace/Jira for FinVault) and Microsoft Entra ID (SharePoint/ServiceNow for RetailStream), keyed by composite {tenant_id}:{user_id} + DPoP jkt so intra-tenant peers cannot replay tokens (HTTP 401).
  • Database RLS & Valkey Bulkheads (pooled_gateway_and_rls.sql): Enforces PostgreSQL/AlloyDB FORCE ROW LEVEL SECURITY via SET LOCAL app.current_tenant_id and isolates noisy neighbors in Memorystore for Valkey.
  • 10/10 Red-Team Breach Simulation Suite (run_breach_simulations.py): Verifies deterministic rejection of forged headers, catalog probing, memory traversal, prompt injection, NLC bypass, PII leaks, SQL RLS escape, RPM floods, 3LO reuse, and DPoP replay.

Pattern B: Zero-Trust Sovereign Silos for Regulated Workloads

Audience: Cloud Architects, CISOs & Compliance Leads in FinTech, Healthcare & Public Sector

1. Executive Thesis & Core Problem Solved

When OCC/FDIC banking rules, EU DORA, HIPAA, FDA 21 CFR Part 11, or FedRAMP prohibit shared compute and shared databases, Pattern B (Sovereign Silos) wraps the unchanged 80% reusable 5-Hop Cymbal core inside a dedicated Google Cloud project per corporate tenant (cymbal-finvault-silo-prod & cymbal-retailstream-silo-prod) with VPC Service Controls, IAM Principal Access Boundaries, a < 5 s customer-held Cloud KMS CMEK kill-switch (HTTP 423 Locked), and air-gapped Gemma 3 (27B) on GKE.

2. Core Technical Architecture & 5-Hop Isolation Mechanics

  • Dedicated VPC-SC Perimeter & IAM PAB (pattern_b_siloed_service.py): Confines principals via Organization IAM v3 PAB and blocks cross-project API exfiltration with HTTP 403 VPC_SC_PERIMETER_VIOLATION.
  • Cloud KMS / EKM < 5 s Crypto-Shredding Kill-Switch: Disabling the tenant's KMS key version triggers targeted Valkey UNLINK {tenant_id}:* (0 peer evictions) and immediately halts in-flight agent turns, memory reads, and AlloyDB queries with HTTP 423 Locked.
  • Vertex AI Dedicated PT & Air-Gapped Gemma 3 on Private GKE (gke_gemma3_airgapped_manifest.yaml): Supports reserved Vertex AI GSUs or private GKE GPU enclaves with 0.0.0.0/0 WAN egress blocked.
  • 6/6 Silo Exfiltration & CMEK Revocation Suite (run_silo_security_tests.py): Certifies dual-tenant silo parity, VPC-SC blocks, PAB confinement, live KMS kill-switch, and zero-WAN GKE routing.

Pattern C: Dynamic Hybrid Routing & Zero-Downtime Tier Upgrades

Audience: Cloud Architects, Platform Product Managers & FinOps Leads Operating Tiered B2B SaaS
🟧 Google Slides ↗ 🟦 Google Doc ↗ 🐙 GitHub MD ↗

1. Executive Thesis & Core Problem Solved

Tiered B2B SaaS platforms typically serve a bimodal 950 Standard + 50 Regulated Enterprise customer portfolio—plus mid-contract Standard → Enterprise upsells. Pattern C (Dynamic Hybrid Hub-and-Spoke) serves every customer from one unified global ingress domain, routing Standard tenants to the shared Pool and bridging Enterprise tenants over Private Service Connect (PSC) to dedicated CMEK spokes with 0 ms-downtime live tier graduation.

2. Core Technical Architecture & 5-Hop Isolation Mechanics

  • Unidirectional PSC Hub-to-Spoke Bridge: Consumer Hub VPC connects to Enterprise Producer Spoke ServiceAttachment endpoints over PSC NAT with zero VPC peering or CIDR overlap, blocking pooled spoke impersonation with HTTP 403.
  • 3-Phase Live Tier Graduation State Machine (pattern_c_hybrid_router_and_migrator.py): Executes SHADOW_SYNC (backfill + SHA-256 parity) → ATOMIC_CUTOVER (sub-ms routing flip, 0 dropped turns) → DRAIN_AND_VERIFY (pooled UNLINK + OTel attestation).
  • Instance-Scoped Profile Isolation & 4/4 Migration Suite (run_tier_migration_suite.py): Upgrades a tenant instance from STANDARD to ENTERPRISE with zero global state bleed across TENANT_PROFILES.
  • Dual-Provider Terraform Blueprint (4.6 main.tf): Declaratively wires google.hub forwarding rules to google.spoke PSC service attachments.
