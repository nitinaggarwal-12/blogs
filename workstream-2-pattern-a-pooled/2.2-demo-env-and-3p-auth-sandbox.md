## 2. Configure Federated Identity Providers (Hop 1 & Hop 5 Auth Sandbox)

### 2.1 Tenant Alpha (`FinVault Bank`) — Google Workspace OIDC + 3LO Scopes
1. In **Google Cloud Console > APIs & Services > Credentials**, create an OAuth 2.0 Client ID for FinVault Bank (`finvault.com` internal/trusted domain).
2. Register the 3LO scopes required by FinVault's Google Workspace & Jira MCP connector in **GCP Agent Identity (Auth Manager)**:
   * `https://www.googleapis.com/auth/drive.readonly` (incident post-mortem runbooks)
   * `https://www.googleapis.com/auth/calendar.events` (scheduling OCC/FDIC regulatory review bridges)
   * `https://www.googleapis.com/auth/gmail.send` (dispatching executive incident briefs)
   * `read:jira-work`, `write:jira-work` (Jira Enterprise incident escalation tickets)

### 2.2 Tenant Beta (`RetailStream Corp`) — Microsoft Entra ID (Zero Google Footprint) + Inline 3LO Consent
1. In **Microsoft Entra Admin Center > App Registrations**, register `Cymbal-RetailStream-Agent-Client`:
   * **Supported account types**: Single tenant (`retailstream.onmicrosoft.com`).
   * **Redirect URI**: `https://edge.cymbal-saas.example.com/oauth2/callback/entra`
   * **API Permissions (Delegated 3LO)**:
     * Microsoft Graph: `Sites.Read.All` (SharePoint incident runbooks)
     * ServiceNow ITOM REST API: `useraccount` (ServiceNow incident & CMDB queries)
2. Register the Entra ID OIDC discovery URL (`https://login.microsoftonline.com/<RETAILSTREAM_TENANT_GUID>/v2.0/.well-known/openid-configuration`) in the Hop 1 Edge Identity PEP (`IDP_ISSUER_MAP`) and Auth Manager.

## 3. Configure Cloud Armor Header Sanitization Rule

To prevent any client from spoofing `X-Tenant-ID: finvault` at the network edge, attach a Cloud Armor security policy with header sanitization on the Global External Application Load Balancer:

```bash
gcloud compute security-policies create cymbal-pooled-edge-waf \
  --description="Cloud Armor WAF + SQLi/XSS + X-Tenant-ID Spoof Protection"

# Block SQLi and XSS at Layer 7
gcloud compute security-policies rules create 1000 \
  --security-policy=cymbal-pooled-edge-waf \
  --expression="evaluatePreconfiguredWaf('sqli-v33-stable') || evaluatePreconfiguredWaf('xss-v33-stable')" \
  --action=deny-403 \
  --description="Block SQLi and XSS payloads at edge"
```

*(Note: The Cloud Run Edge PEP & Envoy Service Extension deterministically strips client-supplied `X-Tenant-ID`, `X-Cymbal-Tenant`, and `X-Cymbal-Tier` headers prior to minting the RFC 8693 OBO + DPoP token).*
