# Workstream 4.2: Setup Hub-and-Spoke Demo Environment (Pattern C — Dynamic Hybrid)

> **Workstream**: Workstream 4 — Hybrid Architecture (Pattern C)  
> **Scope**: Setting up the Central Ingress Hub (`cymbal-hybrid-hub-prod`), the Shared Pooled Compute Plane, and Dedicated Tenant Data/Agent Spokes linked via **Private Service Connect (PSC) Service Attachments**.

---

## 1. Hub-and-Spoke Network & PSC Topology Overview

Unlike VPC Network Peering, **Private Service Connect (PSC)** uses NAT-based producer-consumer service attachments:
* **No IP CIDR Overlap**: Every enterprise tenant spoke project can use the exact same internal subnet range (`10.40.0.0/20`) without conflicting with the Hub or other tenants.
* **Unidirectional Producer Exposure**: The Hub consumer forwarding rule can only initiate connections to the tenant spoke's published PSC `ServiceAttachment`; the tenant spoke cannot initiate lateral connections back into the Hub VPC.

---

## 2. Configure Producer PSC Service Attachment (In Tenant Spoke Project)

```bash
export SPOKE_PROJECT="cymbal-finvault-silo-prod"
export HUB_PROJECT="cymbal-hybrid-hub-prod"
export REGION="us-central1"

# 1. Create dedicated NAT subnet for Private Service Connect in the Tenant Spoke VPC
gcloud compute networks subnets create finvault-psc-nat-subnet \
  --network=finvault-sovereign-vpc \
  --region="${REGION}" \
  --range="10.40.240.0/24" \
  --purpose=PRIVATE_SERVICE_CONNECT \
  --project="${SPOKE_PROJECT}"

# 2. Publish the Tenant Spoke Internal Load Balancer via a PSC Service Attachment
gcloud compute service-attachments create finvault-agent-spoke-psc \
  --region="${REGION}" \
  --producer-forwarding-rule=finvault-spoke-ilb-forwarding-rule \
  --connection-preference=ACCEPT_MANUAL \
  --consumer-accept-list="${HUB_PROJECT}=10" \
  --nat-subnets=finvault-psc-nat-subnet \
  --project="${SPOKE_PROJECT}"
```

---

## 3. Configure Consumer PSC Endpoint (In Central Ingress Hub Project)

```bash
# 1. Reserve an internal IP address in the Central Hub VPC for FinVault's PSC Endpoint
gcloud compute addresses create psc-endpoint-finvault-ip \
  --region="${REGION}" \
  --subnet=cymbal-hub-subnet \
  --addresses="10.10.0.50" \
  --project="${HUB_PROJECT}"

# 2. Create the PSC Consumer Forwarding Rule pointing to FinVault's Service Attachment
gcloud compute forwarding-rules create psc-consumer-finvault \
  --region="${REGION}" \
  --network=cymbal-hub-vpc \
  --address=psc-endpoint-finvault-ip \
  --target-service-attachment="projects/${SPOKE_PROJECT}/regions/${REGION}/serviceAttachments/finvault-agent-spoke-psc" \
  --project="${HUB_PROJECT}"
```
