## 2. GA Migration & Field Enablement Playbook (For FDEs, CEs & Architects)

### Step 1: Discovery & Workload Qualification (15-Minute Customer Triage)
Ask the customer three qualifying questions to select the right starting pattern:
1. **Are you building a B2B SaaS platform with >20 Standard-tier tenants where unit COGS is paramount?** $\rightarrow$ Start with **Pattern A (Pooled)**.
2. **Do 100% of your tenants mandate contractual physical project isolation, customer-revocable CMEK kill-switches, and VPC-SC perimeters?** $\rightarrow$ Deploy **Pattern B (Sovereign Silos)**.
3. **Do you offer tiered SaaS pricing (e.g., Standard/Pro on shared infrastructure + Enterprise/Regulated with dedicated data spokes and custom agents)?** $\rightarrow$ Deploy **Pattern C (Dynamic Hybrid)**.

### Step 2: Live Tier Upgrade Runbook (`Standard Pool -> Enterprise PSC Spoke`)
1. Run the Terraform Spoke module (`workstream-4-pattern-c-hybrid/4.6-terraform-hybrid-psc-blueprint/`) to provision the customer's dedicated GCP project, Cloud KMS CMEK key, and PSC `ServiceAttachment`.
2. Trigger `execute_zero_downtime_tier_upgrade()` to replicate AlloyDB RLS rows (`WHERE tenant_id = '<tenant>'`) and 5-Level Memory Bank namespaces to the dedicated spoke.
3. Verify `replication_lag_ms == 0` and `PSC_CONNECTION_ACCEPTED`, then commit the atomic Firestore route cutover.
4. Confirm in BigQuery OTel logs that subsequent turns route to `PATTERN_C_HYBRID_PSC_SPOKE` with an upgraded `8,000` thinking-token budget and CMEK encryption.
